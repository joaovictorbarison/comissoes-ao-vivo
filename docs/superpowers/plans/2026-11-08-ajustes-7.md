# Ajustes 7 Itens Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the 7 approved adjustments to Comissões Ao Vivo 2: secretary card header with hyphen, secretary shows author/relator/conclusion, process and vote links to ALESP Sem Papel / Legis, remove "Aprovado voto em separado", presence/vista filter to deputados only, per-deputy cabinet with accept flow, and TV 8-second result display with auto-advance.

**Architecture:** Keep existing stack (React+Vite+Tailwind, Express+Socket.io, node:sqlite). Add a `vinculos` table for assessor→deputado pairing with `pendente/aceito/recusado`, change `cabinetKey` to normalized deputy name, and make TV a timed state machine on the front-end (em_votacao > em_discussao > result-8s > next nuOrdem). No new dependencies.

**Tech Stack:** React 18, Vite 5, Tailwind 3, Express 4, socket.io 4, node:sqlite (DatabaseSync), Vitest.

**Spec:** `docs/superpowers/specs/2026-11-07-comissoes-ao-vivo-2-design.md` + approved short design in conversation 2026-11-08 (items 1-7, option A, vista filter extended to assessor-excluded everywhere).

## Global Constraints

- Stack is fixed: React+Vite+Tailwind (front), Node+Express+Socket.io (back), node:sqlite. No new packages.
- Secretary password is `dac2027`, validated on backend; no Legis SSO; biometrics are future-only.
- Meetings list is `status.txNome="Convocada"`, no search/filters. Pauta is all items (?size=500).
- Assessor/Deputado card is Option A (official banner on top). Statuses: em_discussao and em_votacao are distinct.
- Up to 10 simultaneous meetings, each in its own Socket.io room (`reuniao:<idReuniao>`); no data leaks between rooms.
- Private notes visible only to the paired assessor↔deputado of the same cabinet; `cabinetKey` becomes normalized deputy name after this change.
- Secretary status edits are reversible until close; final PDF is snapshot at close; session persists in SQLite.
- Secretary item header is `Item N - <tipo+numero>` with hyphen, same font/color for both parts.
- Secretary card shows below ementa: `Autor: ... • Relator: ... — conclusão`.
- `PL <n/ano>` text links to ALESP Sem Papel (opens new tab); `Relator: ... — conclusão` links to `documentosVoto[0].linkArquivo` (opens new tab).
- "Aprovado voto em separado" button does not exist in secretary panel.
- Only `profile=deputado` registers presence and appears in Presentes and in "Quem solicitou vista?"; assessor never appears in either list.
- Assessor identification includes deputy name; deputy sees pending/accept banner; notes only flow after accept.
- TV shows result (APROVADO/REJEITADO/VISTA: <names>/RETIRADO) for 8 seconds, then advances to next `nuOrdem`, then resumes em_votacao > em_discussao > first.

## Review Focus

- **Typo in deputy name at login** — assessor types "Gil Diniz" vs "Gil Diniz Bolsonaro" and deputy never sees the pending request; reasonable person expects fuzzy suggestion or pending list searchable; pinned by Task 4 test for normalized exact match and pending list.
- **Duplicate presence / stale sessions** — same deputy re-enters meeting in new tab and expects single presence; pinned by Task 3 test for dedupe by `cabinet_key + profile`.
- **TV timer drift / stuck on last item** — after 8s on last item, TV should stay on result or loop to first incomplete, not blank; pinned by Task 5 test.
- **Vote link missing (`linkArquivo` null)** — item without vote document should show plain text, not a dead link; pinned by Task 2 test.
- **Sem Papel URL 404** — `idProcesso` link pattern breaks; fallback to search URL should open; pinned by Task 2 test.

export function semPapelUrl(proc) {
  if (!proc?.idProcesso) return `https://www.al.sp.gov.br/spl/2019/06/Anexos/AP${proc?.idProcesso||''}.pdf`
  return `https://www.al.sp.gov.br/spl/2019/06/Anexos/AP${proc.idProcesso}.pdf`
}
export function votoUrl(vote){ return vote?.linkArquivo || null }
